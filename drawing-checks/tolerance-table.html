Tolerance Table Checker

Paste a dimension table with deviations and measured values. Every row is judged against its own limits, and a value sitting exactly on a limit is called out separately.

Row by row: the lower and upper limit are computed from the nominal and the two deviations, then compared with the measured value. PASS, AT LIMIT or FAIL, with the margin to the nearer limit.

By EnginStack Editorial Team | Reviewed against NIST, BIPM and primary-source documentation About →

One row per line. Columns separated by commas or tabs. A unit written on a value overrides the dropdown, so 0.750 in and 19.05 mm can sit in the same column. Nothing leaves your browser.

What this checks

Every row is a dimension with a tolerance, plus the value someone actually measured. The checker computes the lower and upper limit from the nominal and the two deviations, compares the measured value against both, and returns a verdict for that row. The whole table is read in one pass, so a single out-of-tolerance line cannot hide in the middle of a forty-row inspection sheet.

Four columns means nominal, upper deviation, lower deviation and measured value. Three columns means nominal, a single tolerance cell and measured value, where the middle cell may be written as ±0.003, +0.005/-0.000 or +0.001/-0.004. A value may carry its own unit, so a column that mixes inches and millimeters still compares correctly, because every limit is evaluated in the base unit rather than in whatever number happened to be typed.

How to read the verdict

Three outcomes, and the middle one is the reason this tool exists. PASS means the measured value sits strictly inside the band. AT LIMIT means the value equals a limit exactly: the part conforms, but it conforms with zero margin, and the next measurement of the same feature will probably fall outside. FAIL means the value is past a limit, and the note says which side.

The margin column is the distance from the measured value to the nearer limit. It is the number worth putting in a report, because a row that passes with 0.0002 of margin and a row that passes with 0.004 are not the same news even though both print PASS. Every figure is computed as an exact fraction from the definitions in the same engine the site's converters use, so a limit comparison never turns on a floating-point rounding difference.

Worked example

The sample table is loaded when the page opens. Row two is written in the three-column form: nominal 1.250 in, tolerance ±0.003 in, measured 1.255 in. The limits are 1.247 and 1.253, so 1.255 is 0.002 past the upper limit and the row fails with above upper limit. Row three is nominal 2.000 in with a unilateral band of +0.000 and -0.005, measured 1.994 in: the lower limit is 1.995, so the row fails below by 0.001. Row four measures exactly 0.502 against limits of 0.498 and 0.502, so it is reported as AT LIMIT rather than PASS.

Why check rows instead of numbers

A converter answers one question: what is this value in another unit. That is not where dimensional errors come from. They come from a table where one row was transcribed from a different revision, where a unilateral tolerance was entered as symmetric, or where a deviation was typed with the wrong sign. Those are table-shaped faults, and they need a tool that reads the table.

Because the input never leaves the browser, a supplier inspection sheet or a pre-release drawing can be checked without uploading it anywhere. The CSV export carries the original input text next to every computed limit, so a second person can audit the result against the source without re-running anything.

What it will not do

It does not know your drawing standard and does not apply one. Limits are computed from the numbers you supply, arithmetically. It will not decide whether a tolerance is appropriate for a fit, and it will not account for geometric tolerance, datum shift or measurement uncertainty. Those live in the drawing and in your inspection plan. This tool only answers whether each measured value sits inside the band the drawing states.

Questions

What happens if the upper and lower deviations are entered the wrong way round?

The row is failed with the note tolerance band inverted. A band where both deviations are positive, or where the lower deviation is numerically greater than the upper, produces limits in the wrong order, and silently computing an answer from it would be worse than refusing. The row is still reported so you can see which one it was.

Can a row carry its own unit even when the dropdown says something else?

Yes, and that is deliberate. A unit written on the value wins over the dropdown, so a sheet that drifted into millimeters partway down still compares correctly. If a whole column is in the wrong unit, the unit mix scanner is the tool built to find that.

Is the margin column absolute or signed?

It is the smallest of the two distances to a limit, so it is never negative. The direction of a failure appears in the note instead, as above upper limit or below lower limit, which is easier to act on than a signed number.

Why does a value that equals a limit not simply pass?

It does pass, in the sense that the part conforms. It is reported separately because a part exactly on a limit has no margin left, and in a real inspection that usually means the process, not the part, is the problem. The summary counts it apart from clean passes so a report does not claim more margin than exists.

How many rows can it take?

Several thousand lines run without trouble because each row is independent and the arithmetic is integer based. There is no upload and no request, so the limit is the browser tab rather than a server quota.
