What this checks

Take a value, convert it to another unit at a chosen precision, then convert the result back. If the value you get back is not the value you started with, the conversion is lossy, and any answer printed at that precision is a different number from the one in the source document. This tool runs that loop for every row and reports the smallest number of decimals at which the loop closes.

This is the mechanism behind a familiar complaint: two converters disagree about the same conversion. Usually both are correct, and one of them rounded the intermediate value before converting again. The loss is not a bug in either site, it is arithmetic, but it is worth knowing exactly which values survive a round trip and which do not.

How to read the verdict

CLOSED means the round trip returned the original value exactly. The row also shows the minimum number of decimals at which that happens, which is often smaller than people expect: 25.4 mm is exactly one inch, so zero decimals closes it. LOSSY means the round trip returned something else, and the note gives the size of the loss in the target unit.

A row marked never closes at any dp is the most interesting case. It means no finite number of decimals can represent the value in the target unit, because the conversion is a repetition. One third of an inch is the standard example: in millimeters it is 8.4666 and the sixes never end.

Worked example

Row one is 1 in converted to millimeters at zero decimals. The conversion gives 25.4, which prints as 25, and 25 mm converts back to 0.984 in. The loss is 0.4 mm and the row reports that one decimal is enough to close it, because 25.4 mm is exact. Row three is 1/3 in, which never closes: its millimeter value is a repeating decimal, so the loop can be made arbitrarily accurate but never exact.

The practical reading is direct. If a drawing states a dimension in one unit and the shop works in the other, the number of decimals needed to close the round trip is the number of decimals needed to avoid an argument later.

Why the loop matters more than the conversion

A single conversion has one rounding step and almost always looks fine. The failure mode appears when the value passes through a conversion a second time, which is exactly what happens when a drawing is converted to metric, a feature is inspected in metric, and the inspection report is converted back to inches for the customer. Each pass is defensible on its own and the accumulated difference is not.

Because the arithmetic is exact until the moment of printing, the loss reported here is caused by your chosen precision alone. Nothing in the tool adds error of its own.

What it will not do

It does not tell you what precision to use, and it does not model measurement uncertainty. A value can close its round trip and still be a poor dimension to put on a drawing. What it does tell you is the arithmetic floor: below that precision, the two documents describe different sizes.

Questions

Why does the same conversion give a different answer on a different website?

Because most converters round the intermediate value before converting again, and they differ in where they round and to how many places. This checker exists to measure that effect rather than argue about it: pick the precision, run the loop, and the size of the discrepancy is stated in the target unit.

What does "closes at 2 dp" mean exactly?

It means that formatting the converted value to two decimal places and converting that back reproduces the original value exactly, as a fraction, not approximately. Zero decimals may not close while two do, which is why the minimum is computed by trying each precision from zero upward rather than guessed from the size of the number.

Is a value that never closes therefore wrong?

No. It means the value has no finite decimal representation in the target unit, so the conversion is inherently approximate. One third of an inch is real and correct and still cannot be written as a finite number of millimeters. The honest thing to do with such a value is to state the unit it was defined in.

Does it handle fractions like 3/8 and feet and inches pairs?

Yes. The same parser that reads the site feet and inches calculator is used here, so 3/8 in, 1 1/2 in and 5 ft 10 1/2 in are all read as exact fractions before any conversion happens.

What precision should a metric drawing carry?

The narrowest tolerance on the drawing decides it, not the nominal sizes. A rule that works: carry one more decimal than the tightest tolerance needs, then check the round trip for the values that matter. The tool will show you where that breaks down.
